# Бриф на сайт

Универсальный бриф для клиентов: пошаговые вопросы с подсказками и примерами, живой макет будущего сайта, отправка ответов с файлами на почту и в Telegram и автоматический черновик КП в Google Docs.

**Страница:** https://elenasamanchuk.github.io/site-brief/

## Какую ссылку отправлять

| Кому | Ссылка |
|---|---|
| Любой клиент | `https://elenasamanchuk.github.io/site-brief/` |
| Кафе и рестораны — сфера уже выбрана | `https://elenasamanchuk.github.io/site-brief/?sphere=food&tag=batski-fasol` |

- `sphere` — заранее выбранная сфера: `food`, `beauty`, `health`, `edu`, `services`, `shop`, `tourism`, `expert`
- `tag` — метка, которая придёт в Telegram (`#batski-fasol`) и в журнал: удобно понимать, от кого бриф

## Как устроено

- **Главное** — 7 шагов, 10–15 минут: контакты, бизнес, задачи, формат, функции (базовые — уже отмечены под сферу, расширенные — «сразу / потом»), фирменный стиль, сроки и бюджет. После этого бриф уже можно отправить
- **Детали** — по желанию: клиенты и конкуренты, разделы, товары и меню, для кафе — меню, доставка и банкеты, запись, заказ и оплата, тексты и фото, дизайн, после запуска, продвижение, домен и документы
- **Живой макет** справа (на телефоне — кнопка «Сайт») собирается из ответов: название, сфера, формат, функции, стиль и фирменные цвета
- Черновик ответов сохраняется в браузере клиента; файлы — нет, их нужно прикрепить перед отправкой
- Суммы клиент не видит нигде: ни в брифе, ни в письме ему

## Что приходит после отправки

- **Telegram** (бот @mybrif29375bot → тебе в личку): кратко о клиенте, блок «Для тебя» с оценкой по объёму и бюджету, файлом — бриф целиком, черновик КП и все прикреплённые файлы
- **Почта** elenasamanchuk@gmail.com: все ответы, внутренний разбор, во вложениях — бриф, КП и файлы клиента (если больше 18 МБ — ссылка на Диск)
- **Google Диск**, папка «Брифы — сайты»: на каждый бриф своя папка с файлами, `answers.json` и **черновиком КП в Google Docs** — там строки «___ BYN», суммы вписываешь сама

## Подключить отправку (один раз, ~5 минут)

1. Собрать файл для Google: `node tools/build-gas.mjs` → появится `apps-script/dist/paste-into-google.gs` с токеном бота, chat id и почтой (файл в git не попадает, настройки — в `apps-script/secrets.local.json`)
2. Открыть https://script.google.com под аккаунтом elenasamanchuk@gmail.com → «Новый проект», назвать «Бриф на сайт»
3. Удалить всё в `Код.gs`, вставить содержимое `paste-into-google.gs`, сохранить
4. Сверху выбрать функцию **setup** → «Выполнить» → разрешить доступы (Google предупредит «приложение не проверено» — это ваш собственный скрипт: «Дополнительно» → «Перейти»). Придут тестовое сообщение в Telegram и письмо
5. «Развернуть» → «Новое развёртывание» → тип «Веб-приложение»: запуск от имени «Я», доступ «Все» → «Развернуть» → скопировать адрес `…/exec`
6. Вписать адрес в `config.js` → `endpoint` и запушить (или прислать адрес — впишу)

После правок `Code.gs` или `Proposal.gs`: заново собрать файл, вставить, затем «Развернуть» → «Управление развёртываниями» → карандаш → «Версия: новая». Адрес `…/exec` при этом не меняется.

## Где что править

| Что | Файл |
|---|---|
| Вопросы, варианты, подсказки, примеры | `assets/schema.js` |
| Работы в галерее и примеры | `assets/schema.js` → `BRIEF_WORKS`, картинки — `assets/works/` |
| Живой макет | `assets/preview.js` |
| Ставки для внутренней оценки, скидка «для своих», тексты КП | `apps-script/Proposal.gs` → `KP` |
| Письмо и Telegram | `apps-script/Code.gs` |
| Стиль | `assets/brief.css` |

Id полей и value вариантов из `schema.js` используются в `Proposal.gs` — при переименовании поправить и там.

## Проверка

```bash
node tools/lint-copy.mjs
```

Проверяет тексты: без точек в конце абзацев и двойных пробелов. Неразрывные пробелы после коротких слов и перед тире страница расставляет сама.

Локальный прогон без Google — сайт на 5601 и мок скрипта на 8787, автотест проходит бриф как клиент, проверяет живой макет, отправку, ширины 360–1440 и складывает письмо, сообщения Telegram и КП в `tools/out/`:

```bash
python3 -m http.server 5601
```
